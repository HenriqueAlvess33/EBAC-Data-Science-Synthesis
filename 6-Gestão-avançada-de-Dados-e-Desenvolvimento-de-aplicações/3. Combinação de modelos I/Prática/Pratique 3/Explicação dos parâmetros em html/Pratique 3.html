Pratique 3

  1. Quais são os hyperparâmetros do RF ?
  1. Para que serve cada um deles ?
Parâmetros
  • n_estimators → Número de árvores utilizadas
  • criterion: ["gini", "entropy", "log_loss"], default="gini" → Função utilizada para mensurar a qualidade de uma divisão, o método mais utilizado, atuando como padrão seria o gini que se baseia na impureza de gini
    CriterionInterpretaçãoPerformanceProbabilidades boas?
    giniImpureza simplesRápidoRegular
    entropyInformação (mais preciso)MédioLevemente melhor
    log_lossOtimiza probabilidade preditaMais lentoSim, muito melhor
  • max_depth, default=None → Informa a profundidade da árvore, caso seja deixado no valor padrão de None, os nós irão se dividir até que as folhas estejam totalmente puras, ou até atingirem o valor mínimo de amostras por divisão.
  • min_samples_split: int or float, default=2 → O número mínimo de amostras necessárias para se dividir um nó. Caso seja do tipo de dado int , então o valor dado em min_samples_split é o determinado para mínimo de amostras nas folhas, caso seja do tipo float, então o número mínimo de amostras é determinado pela seguinte operação ceil(min_samples_split * n_samples)
  • min_samples_leaf: int or float, default=1 → Número mínimo de amostras por folha, ao se realizar o último split, ambas as folhas necessitam estar com o número mínimo de amostras, caso contrário ambas são desconsideradas e retornam para o momento prévio a divisão. Caso seja do tipo de dado int , então o valor dado em min_samples_split é o determinado para mínimo de amostras nas folhas, caso seja do tipo float, então o número mínimo de amostras é determinado pela seguinte operação ceil(min_samples_split * n_samples)
  • min_weight_fraction_leaf: float, default=0.0
    • Como funciona?

      Ao invés de contar o número de amostras como min_samples_leaf, ele usa o peso das amostras (caso você esteja usando o parâmetro sample_weight no fit()).

      Então:

    • Cada divisão precisa deixar, em cada lado, pelo menos uma fração min_weight_fraction_leaf do peso total dos dados de treino.
    • Exemplo prático:

      Se você tem:

      1000 amostras

      peso total (somando tudo): 1000 (se cada uma tem peso 1)

      min_weight_fraction_leaf = 0.02

      → Cada folha precisa conter pelo menos 2% do peso total, ou seja, 20 unidades de peso.

  • max_features: [”sqrt”, “log2”, None], int or float, default=”sqrt” →
    • O número de atributos a considerar ao procurar o melhor split:
      • Se for um número inteiro (int), então serão considerados exatamente max_features atributos em cada divisão.
      • Se for um número decimal (float), então max_features representa uma fração, e serão considerados

        max(1, int(max_features * n_features_in_)) atributos em cada divisão.

      • Se for "sqrt", então max_features = sqrt(n_features).
      • Se for "log2", então max_features = log₂(n_features).
      • Se for None, então max_features = n_features.
  • max_leaf_nodes: int, default=None → Defini um número máximo de nós, definido como None é entendido como um número ilimitado
  • min_impurity_decrease: float, default=0.0 
    N_t / N * (impurity - N_t_R / N_t * right_impurity
                    - N_t_L / N_t * left_impurity)

    Essa fórmula mede quanto a divisão ajuda a reduzir a impureza total, levando em conta o tamanho dos nós filhos e os pesos das amostras (se houver).

    Se essa redução for maior ou igual ao min_impurity_decrease, a divisão é aceita.

  • bootstrap: bool, default=True → Se setado para False, todo o conjunto de dados será usado na construção de cada árvore
  • oob_score: bool or callable, default=False → Disponibiliza os dados “out-of-bag” para serem usados afim de estimar a capacidade de generalização das árvores, por padrão é utilizado accuracy_score para realizar a medição mas é possivel criar funções personalizada para utilizar com a assinatura metric(y_true, y_pred)

    Modelos como RandomForest treinam várias árvores de forma independente → perfeito para paralelização!

    Com n_jobs, você controla quantos núcleos de CPU serão usados:

    Valor de n_jobsComportamento
    1 ou NoneUsa só 1 núcleo da CPU
    -1Usa todos os núcleos disponíveis
    2, 4, etc.Usa 2, 4, etc. núcleos

  • random_state: int, RandomState instance ou None, default=None

    Controla a aleatoriedade da amostragem com reposição dos dados (bootstrap=True) durante a construção das árvores, bem como da seleção aleatória de atributos em cada divisão (max_features < n_features).

    Atribuir um valor fixo (ex: random_state=42) garante a reprodutibilidade dos resultados, essencial em experimentos científicos ou comparações entre modelos.

  • verbose: int, default=0

Controla o nível de verbosidade durante a execução dos métodos fit e predict.

  • 0: execução silenciosa (padrão).
  • Valores inteiros maiores: maior detalhamento dos logs impressos no terminal, útil para depuração ou monitoramento do progresso do treinamento.
  • warm_start: bool, default=False

Quando configurado como True, reutiliza a solução da chamada anterior do método fit, acrescentando mais estimadores (árvores) ao conjunto. Caso contrário, um novo modelo é treinado do zero.

Este parâmetro é útil para treinamento incremental ou ajuste progressivo do número de estimadores.

  • class_weight: {“balanced”, “balanced_subsample”}, dict ou list of dicts, default=None

    Define os pesos atribuídos a cada classe.

    • Se None, todas as classes recebem peso 1.
    • "balanced": calcula pesos automaticamente com base na frequência inversa das classes, segundo a fórmula:

      pesoc=namostrasnclasses×freq(c){peso}_c = \frac{n_{\text{amostras}}}{n_{\text{classes}} \times \text{freq}(c)}pesoc​=nclasses​×freq(c)namostras​​﻿

    • "balanced_subsample": aplica o mesmo cálculo acima, mas com base apenas nas amostras selecionadas no bootstrap de cada árvore.
    • dict: permite especificar manualmente os pesos (ex: {0: 1, 1: 5}).
    • list of dicts: usado para problemas multioutput, sendo fornecido um dicionário por coluna de saída.

      Os pesos especificados serão multiplicados por sample_weight caso este seja informado durante o fit.

  • ccp_alpha: float ≥ 0.0, default=0.0

    Parâmetro de poda baseado na complexidade da árvore (Cost-Complexity Pruning).

    Controla o nível de poda aplicado após o treinamento. Subárvores com custo-complexidade inferior ao ccp_alpha são eliminadas.

    Quanto maior o valor de ccp_alpha, mais agressiva será a poda, resultando em modelos mais simples e, potencialmente, com menor overfit.
